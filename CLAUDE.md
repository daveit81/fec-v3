# FEC v3 — working notes for agents and humans

FreeExtraChips.com is leaving Joomla 2.5 / PHP 5.6 for this Laravel 13 + Filament 5 application,
one page at a time (strangler migration). The roadmap, decisions and runbooks live in the
"FreeExtraChips" Claude project (`FEC-v3-piano-migrazione.md`, `FEC-v3-migrazione-server-runbook.md`).

## Where it runs

- Server: KnownHost managed dedicated, AlmaLinux 9 + CloudLinux 9, cPanel, LiteSpeed. Account `freeextr`.
- App root `/home/freeextr/fecv3/`, docroot `/home/freeextr/fecv3/public` = `https://v3.freeextrachips.com`
  (Cloudflare proxied, behind Cloudflare Access; origin accepts only Cloudflare IPs).
- PHP 8.4 is the CloudLinux alt-php: CLI `/opt/alt/php84/usr/bin/php`, web via
  `AddHandler application/x-httpd-alt-php84 .php` in `public/.htaccess`. Inside CageFS every
  `/opt/cpanel/ea-php*/bin/php` and `/usr/local/bin/php` is the Selector's PHP 5.6: never use them.
- Composer: `/opt/alt/php84/usr/bin/php /home/freeextr/bin/composer`.
- Run everything as `freeextr` (no `su`/`rsync` inside the cage; root-owned files break the app).
- Deploy: this repository (`daveit81/fec-v3`) is the only channel. Claude pushes to `main`,
  the server pulls with a read-only deploy key: `cd /home/freeextr/fecv3 && git pull`.
  Never edit code on the server by hand.

## Legacy snapshot

- `legacy/` is a text-only, read-only copy of our Joomla-era code taken with
  `scripts/legacy-snapshot.sh` (run as freeextr on the server, then committed from there). It is
  the input of the mechanical port into `app/Fec/Legacy/`; never deploy, autoload or hand-edit it.

## Compatibility layer (phase 2+)

- `app/Fec/Legacy/Joomla/` provides the Joomla 2.5 classes our components call (JFactory, JRequest,
  JUri, JRoute, JDocument, JPagination, the database API, JController/JView/JModel) over Laravel;
  `Runtime::boot()` defines `_JEXEC`/`JPATH_*` and aliases the global names per request.
- Ported components live under `app/Fec/Legacy/site/` (the virtual `JPATH_SITE`), excluded from the
  Composer classmap; `ComponentRunner` is the `PageHandler` that runs them inside the `.fecx` layout.
  Edits to the copies are listed in `app/Fec/Legacy/PORT-NOTES.md`; lib functions come in slices
  generated by `php scripts/lib-slice.php` from `app/Fec/Legacy/lib-slices.json` (the closure of the
  seeds, plus the lib's constants and file-scope statements: the lib publishes `$countries_array`,
  `$currency`, `$bonustype` to `$GLOBALS` when included, and its functions read them there).
- `php artisan fec:parity <path>...` compares the live page and the v3 rendering (status, title,
  metas, canonical, stylesheets, JSON-LD, body); every switch needs it green on the section's URLs.
- Public pages are stateless (routes/stateless.php fallback, no cookies). Desks need the redazione
  login (`/desk/login`: password + emailed code; accounts via `fec:user:create`), run on `fec_rw`,
  see `JFactory::getUser()` as the account's `joomla_user_id`, and keep Joomla's own token check
  (`JRequest::checkToken`), so their paths are excluded from Laravel's CSRF middleware.
- Joomla's non-SEF entry `/index.php?option=...` reaches Laravel as the path `/` (the front controller
  is stripped from the URI): the root route hands every request with `option=` to `LegacyDeskController`,
  GET and POST, so a `Route::match(..., '/index.php')` never matches. `JRoute::_()` appends to the SEF
  path the variables the registry URL does not encode (`/methodology-admin?edit=fxcheck`, `start=`), as
  sh404SEF did; messages enqueued before a redirect are flashed in the session and rendered as Joomla's
  `#system-message` block (empty container on public pages).
- `JTable::getInstance('Content')` is `Joomla\Table` + `Tables\Content`/`Tables\Asset` with Joomla 2.5
  semantics: bind only known columns, `check()` (title, alias, dates, meta), `store()` stamps
  created/modified and keeps the article's node in `jos_assets` under the category's asset (nested set:
  insert as last child, leaf move). `JFactory::getCache($group)->clean()` deletes Joomla's file cache
  of that group in `public_html/cache/` so www shows what a v3 desk saved.
- The snapshot crons of com_authors run as `fec:payout-index:snapshot` and `fec:licence-watch:snapshot`
  (`ComponentRunner::runTask()`: the cron's request rebuilt in the console, key from
  `fec.legacy.editions_config`, the task's JSON and HTTP status as output and exit code). Their
  schedule in `routes/console.php` is gated by `FEC_LEGACY_SCHEDULE_SNAPSHOTS`: on only once the
  crontab lines that call them on Joomla are removed, never both.
- Phase 3 (com_bonuses): the component is copied verbatim too (`PORT-NOTES.md` lists what is left
  out), its lib closure is the "bonuses" slice (197 functions), its nine public views are in
  `Dispatcher::HANDLERS`, `com_bonuses.ads` is a writing view (click log). Its URLs are built by the
  sh404SEF plugin `legacy/components/com_bonuses/sef_ext/com_bonuses.php`, not by a router: `JRoute`
  needs its port for URLs the registry does not have. `fec:legacy:check` includes only files that
  declare classes or functions; template-style helpers are parsed, not run.
- While a component runs, `LegacyErrors` turns PHP notices/warnings/deprecations into lines of
  `storage/logs/legacy-notices.log` (first occurrence per file:line, page key in front) instead of
  the exceptions Laravel would raise: PHP 5.6 code warns where Joomla never showed anything. Fatal
  errors and exceptions still fail the request. The runner also copies the request's server
  variables into `$_SERVER` (REQUEST_URI, HTTP_REFERER...) for console runs (parity, snapshots).
- `JPATH_SITE` is the virtual docroot (code); `JPATH_ROOT` is the real `public_html`
  (`fec.legacy.docroot`): the desks' uploads (`images/rtp`, `images/blog`) land where the live site serves them.
- PHP 5.6 sorted with an unstable quicksort, PHP 8 sorts stably: with tied scores the two show
  different rows. Every `usort/uasort/asort/arsort` of the ported code is rewritten to
  `fec_php5_*` (`App\Fec\Legacy\Php5Sort`, the PHP 5.6 algorithm) by the slicer and by
  `php scripts/legacy-port.php <dir>` (run after every copy; `fec:legacy:check` fails on a sort left behind).

## Databases

- Default connection (`DB_CONNECTION`, SQLite for now): framework tables only (sessions, cache, jobs, users).
- Connection `fec`: the live legacy catalogue `freeextr_fec25`, prefix `jos_`, **read-only user**
  during phase 0/1. Our own tables (`jos_bonuses`, `jos_fec_*`, `jos_atlas_*`, …) keep their names
  and ids; `jos_content`, `jos_jreviews_content`, `jos_sh404sef_urls` are read as they are.
- Secrets live only in `.env` on the server (never committed).

## Rules

- Parity, not improvement, until Joomla is switched off: same URLs, same markup (`.fecx`,
  `fec-edition.css`), same data. Improvements belong to phase 6.
- ASCII in PHP string literals; raw UTF-8 only in Blade/CSS files.
- No debug logs under the docroot; never log request payloads or user arrays.
- Every switch of a section is preceded by a parity script and followed by a rollback path
  (one line in the legacy `.htaccess`).

## Desk Lint

- `php artisan fec:desk-lint --probe` prints the value distributions the rules rely on; calibrate
  `FEC_BONUS_ACTIVE_WHERE`, `FEC_BONUS_WELCOME_TYPES`, `FEC_BONUS_CURRENCIES` from it.
- Rules live in `app/DeskLint/Rules`, one class each, explicit SQL with `$this->t('table')` for the
  prefix (the query builder prefixes aliases too, so never `table('bonuses as b')` with raw columns).
- JReviews checkbox flags (`jr_closed`, `jr_suspended`, `jr_blacklisted`) are set when non-empty
  (`*yes*`, `*susp*`, `*bl*`), never compared to "yes".
- Memory table `desk_lint_findings` (framework DB); `--dry-run` leaves it untouched.
- `stale_active` is a review queue (the `FEC_DESK_LINT_STALE_QUEUE` oldest live bonuses) with the
  backlog size in `summary()`; a rule that reports a head of a backlog does the same, never the whole list.
- Report clock is `fec.timezone` (Europe/Rome); storage stays UTC.

## Router (phase 1 kernel)

- `App\Fec\Url\Router::route($path)` decides every GET that no explicit route claims
  (`Route::fallback` → `FrontController`): `jos_sh404sef_urls` first (a known URL is served, or
  redirected to its stored spelling), then the run-time patterns (`app/Fec/Url/Patterns`, e.g.
  `/bonuses/<casino>/<slug>-id<bid>`), then `jos_redirection` — Joomla's redirect plugin only ever
  fired on a 404, so its rules apply to paths nobody else knows.
- A ported view = one `PageHandler` class registered in `Dispatcher::HANDLERS` under `option.view`.
  Unregistered views answer 404 (with the decision shown on the dev hostname only).
- Probes: `php artisan fec:urls:resolve <path>...` (`--json`) and `GET /__registry?path=` on `v3.`.
- A request that differs from the registry's spelling only by the trailing slash (`/bonuses` for
  the stored `bonuses/`) is a 301 to the stored spelling, as sh404SEF answered; a page's canonical is
  the registry spelling, slash included. `JUri` keeps the request's trailing slash too.
- Aliases (rank > 0) are served as pages with a self-referencing canonical, as Joomla does
  (`FEC_ROUTER_ALIAS_REDIRECT=false` is parity; true is a phase 6 option).
- Redirect targets (`index.php?...`) resolve to a SEF path exactly, then tolerantly (parameter
  order, `lang`, `Itemid` ignored); `fec:urls:stats --redirects` audits the 3.8k rules.
- Stateless endpoints (no cookies) go in `routes/stateless.php`, never in the `web` group.
- The closures in `bootstrap/app.php` run while the kernel is resolved, before the configuration is
  loaded: never call `config()` there (it kills every request and every artisan command); anything
  that depends on config goes in `AppServiceProvider::boot()`.
